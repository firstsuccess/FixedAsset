# アプリ独自認証への差分移行 — v0.7.0 / Business Schema 2 / Auth Schema 1

対象SiteのID、URL、公開範囲、D1 bindingを維持。ChatGPTの認証ヘッダーとサインイン/サインアウト経路を業務認証に使用しない。

## データ保持
既存users.idを変更せず、所有者メールに対応する既存管理者へadmin1のauth_accountsを一度だけ追加。表示名は管理者。移行はsystem_parameters.local_auth_v1とCASで冪等化。既存会社・資産・仕訳・マスタ・履歴は初期化しない。失敗した移行で管理者が置き換わらない。

## 認証
- ソルト付きPBKDF2-SHA256 100,000回、事前HMAC-SHA256 pepper。WorkersのPBKDF2反復上限に合わせる。pepperはSitesのsecretに保存し、DB・Git・公開移行zipに含めない。
- 初期パスワードは初回変更必須。公開Siteの共通初期パスワードの第三者による先取りを防ぐため、最初の管理者はsecretにハッシュを保存した初期設定コードも提示する。
- 新規/変更パスワードは12〜128文字、制御文字禁止。ハッシュ・pepper・平文パスワードを状態APIや監査ログへ出力しない。
- ランダム256bitセッショントークンを__Host- Cookieで保存。Secure/HttpOnly/SameSite=Strict/Path=/。DBにはSHA-256ハッシュのみ、8時間の絶対有効期限。
- 全業務APIでユーザー有効状態・session_version・会社権限を毎回確認。初回変更未完了では業務APIを拒否する。
- POSTは同一OriginとJSON必須。認証API入力は8KB上限。認証レスポンスはno-store。
- login_idはtrim後にASCII小文字へ統一、英数字/._-の3〜64文字。DB一意制約。既存メール・UUID・履歴は維持。

## ロックと管理
- 一般アカウントは5回失敗で15分ロック。自動/管理者解除を監査する。
- admin1の例外はauth_accounts.user_idに紐付く。ID変更で保持。誤パスワードは拒否。例外は有効なSystem Administrator1名、部分一意indexとサーバーCASで同時変更を制御。
- 全アカウントに接続元IPの20回/分制限。cf-connecting-ipのみを信頼し、欠落時は共通unknownバケット。再認証とリセット完了にも適用する。IPは監査/制限テーブルにハッシュで保存。
- ユーザーの作成/編集・ロック解除・例外移管・リセット発行はSystem Administratorのパスワード再認証必須。従来どおりユーザー管理権限はシステム管理者のみ。
- 表示名・所属会社/部門・ロール・有効状態を編集可能。会社別権限は複数会社を維持し、選択した会社の権限を変更。System Administratorへ昇格時は会社別権限を整理。
- ユーザー情報変更時は対象の全セッションとリセットコードを破棄。自身の編集では再ログインを要求する。パスワードハッシュ・作成日時・最終ログイン日時・過去の操作者UUIDは変更しない。
- パスワード変更・リセット後も全セッションを失効する。

## リセット・復元・移行
- 管理者が30分有効・一度限りの256bitコードを発行。DBにはハッシュのみ。本人がリセット画面で新パスワードを設定。メール送信は未設定であり自動メールリセットは行わない。
- 有効な管理者全員がパスワードを失った場合のセルフサービス回復は未実装。運用上は別の管理者を用意する必要がある。
- 業務バックアップにauthentication.version=1 / accounts（パスワードハッシュを含む）を追加し、業務部分Schema2の互換性を維持。セッション・リセットトークン・IPバケットはバックアップに含めない。
- 認証情報の復元には管理者パスワードの再認証も要求し、盗まれたセッションだけでパスワードを置き換える操作を拒否する。復元時はUUID・会社/部門参照・一意ID・ハッシュ形式・有効な例外管理者1名を検証。トランザクションで業務と認証を復元し、全セッションとリセットコードを破棄。
- 旧バックアップでは現行認証情報を復元対象ユーザーUUIDで保持。例外管理者を保持できない旧バックアップは拒否し、推測で新アカウント/パスワードを作らない。
- 外部Node.js/RDBMSへの移行には同じAUTH_PEPPERを安全に移管する必要がある。pepperを失うと既存ハッシュを検証できない。auth-schema.jsonとSQLite/PostgreSQL DDLへ4認証テーブルを追加。
